Vita — complete wireframe

A local-first encrypted personal companion: voice journal, AI-assisted capture, Tasks, Diary, Vault and Lior. The wireframe consolidates the architecture discussed in the supplied project conversation, including the five-tab navigation, ADHD-oriented hierarchy, privacy boundaries, Lior interaction model and recovery/anti-hallucination rules.

Core premise: everything important should have a visible front door, important information should be available immediately, deeper content can be reached by vertical scrolling or search, and the interface must never become a noisy dashboard. The project is Kotlin + Jetpack Compose, Android 10+, with a privacy-first, local encrypted vault and explicit—not silent—cloud fallbacks.

Non-negotiable behavior

  • Privacy-first: no hidden telemetry, behavioral surveillance, eye tracking or silent cloud processing.
  • Literal First: extraction must preserve what was actually said; uncertain inference stays neutral and is surfaced for confirmation.
  • Lior is a skilled presence: adaptive between reflective companion and pragmatic organizer, never reduced to a generic chat UI.
  • ADHD hierarchy: front-load the important thing, cap simultaneous choices, avoid horizontal hiding, and use progressive disclosure.
  • Transparency: local/cloud execution state and any fallback are visible and explicit.

The privacy model is part of the UX, not a hidden implementation detail.

07 — Behavior, state machines & anti-hallucination flows

Voice → memory flow

1. Capture
Voice or text enters locally.
2. Preserve source
Keep raw transcript/content independently.
3. Literal First
Extract only explicit supportable structure.
4. Confidence gate
High confidence can be routed; uncertainty stays neutral/staged.
5. User-visible result
Scratchpad, confirmation or explicit auto-routing policy.

Extraction rules

  • Never transform a wish into an invented plan.
  • Never transform emotional language into a diagnosis.
  • Keep original wording accessible beside summaries.
  • Separate classification confidence from factual truth.
  • Use conservative schemas: type / literal content / source span / confidence / destination / requires_confirmation.

Notifications

Anchor task
One discreet morning notification for the primary focus.
Secondary tasks
Grouped gentle nudges in chosen windows, never notification spam.
Missed work
No red shame counters. Roll forward or return to backlog.

Memory/project clustering

New content can be associated with a project hub when local semantic confidence is sufficiently strong. Lower-confidence association should surface a small confirmation prompt such as “Link to Vita?” rather than silently fabricating structure.

Important architecture principle: isolate STT, extraction, conversational inference, embeddings and storage behind interfaces. The UI should consume capabilities and execution states, not know which model/provider implementation is underneath. This makes local-only, hybrid and future model changes survivable.

10 — Decisions intentionally not locked

This prevents the wireframe from pretending unresolved discussion points were final requirements.

Memory decay policy
Automatic fading/archive vs user-invoked review was explicitly deferred for later.
On-device vs conversational hybrid
The desired experience requires genuine conversation. The exact provider/runtime/privacy contract must be finalized before implementation.
Task selection policy
Task decomposition is mandatory; the final mix of automatic “one thing”, user choice and energy mapping needs final UX rules.
Backup & recovery UX
Encrypted .vita export and/or P2P sync need a final threat model and recovery design.
Sensorial shortcut
Manual low-stimulus mode is aligned with privacy; exact trigger/placement remains open.
